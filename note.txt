
● What this repo does: It's a Python 3.14 project template with almost no code yet: one main()
  that prints a line, plus one smoke test. Most of the repo is tooling: a dev container, a local
  Ollama model, the SkillSpector scanner for third-party skills, pre-commit hooks, CI, and an
  optional Grafana/Prometheus/Loki dashboard. I assumed the load is one developer on one machine,
  with CI running on every push.

  I ran pytest, just test, ruff check and ruff format --check, and read every config file and
  script.

  Must fix

  1. The only test fails (src/test/test_smoke.py:5)
     - What this is: A smoke test that checks the package imports and has a version.
     - Problem: It reads test_repository.__version. That attribute doesn't exist; the name is
       __version__. It also lives in the wrong file: __version__ is defined in the root
       __init__.py, while src/test_repository/__init__.py is empty. Running it gives
       AttributeError.
     - Fix: Move __version__ = "0.1.0" into src/test_repository/__init__.py, delete the root
       __init__.py, and assert test_repository.__version__.
     - If we skip it: CI is red on every push, and the pre-commit hook blocks every commit that
       touches src/.
  2. The coverage gate fails even after the test is fixed (src/test_repository/main.py)
     - What this is: Coverage means the share of code lines the tests actually run. The project
       requires 80% overall and 75% per file.
     - Problem: Nothing calls main(), so main.py is 0% covered and the total is 33%.
     - Fix: Add a test that calls main() and checks the output with pytest's capsys. That's about
       3 lines.
     - If we skip it: CI and commits stay blocked.
  3. Tests are in a folder no tool looks at (justfile:14, pyproject.toml coverage omit,
     .pre-commit-config.yaml files:)
     - What this is: Each tool needs to know where the tests are.
     - Problem: The tests are in src/test/. But just test runs ./test/, coverage excludes
       tests/*, pre-commit watches ^(src/|tests/), and CLAUDE.md says tests/. Right now just test
       finds 0 tests and exits with code 4. Test files are also counted as covered source code,
       which inflates the coverage number.
     - Fix: Move src/test/ to tests/ at the repo root and set the just test default to tests/.
       Everything else already expects that folder.
     - If we skip it: just test never runs anything, and the coverage numbers are wrong.
  4. The skill-scan CI job lets broken scans through, and fails when there are no skills
     (.github/workflows/skill-scan.yml)
     - What this is: The CI gate that should block dangerous third-party skills.
     - Problem: Both scans use continue-on-error. If a scan crashes (exit 2), report.json is
       missing or has no recommendation, nothing in the case matches, and the step passes. That's
       fail-open, which the project's security contract says must not happen. Separately,
       there's no skills/ folder yet, so the SARIF upload fails on every PR.
     - Fix: Add a *) branch that runs exit 1, and skip the job when skills/ doesn't exist (if:
       hashFiles('skills/**') != ''). Also drop '**/*.md' from the push paths, so docs edits
       don't trigger it.
     - If we skip it: A scan error looks like "safe", and every PR shows a red check you can't
       fix.
  5. Tools are installed unpinned, but the docs say they're pinned (.devcontainer/post-create.sh)
     - What this is: The container setup script that installs uv, just, codegraph, Continue and
       headroom.
     - Problem: CLAUDE.md says "pinned versions in post-create.sh", but everything installs the
       latest version (curl | sh, npm install -g with no version, uv tool install headroom-ai). A
       bad or compromised release lands on the next rebuild with no warning. Also, the codegraph
       npm install -g line has no || warn, so under set -e one npm failure stops the rest of the
       setup.
     - Fix: Add explicit versions, for example @colbymchenry/codegraph@X.Y.Z,
       headroom-ai[mcp]==X.Y.Z and UV_VERSION, plus || warn on that npm line.
     - If we skip it: A rebuild can break, or pull a tampered package, and nobody will know which
       version changed.
